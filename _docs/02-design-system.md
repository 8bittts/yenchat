# Design System

Themes and the generated catalog, the public web design system, and Phosphor typography for YEN.

## Sources of truth

| Path | Role |
|------|------|
| `yen-terminal/customizations/themes/` | YEN-owned themes; win over upstream on a name collision |
| `yen-terminal/customizations/theme-curated-manifest.txt` | The shipped picker catalog, 16–24 themes: the three YEN themes plus widely used community palettes |
| `yen-terminal/customizations/theme-curated-tags.txt` | Search tags: `dark`, `light`, `retro`, `neon`, `low-contrast`, `high-contrast` |
| `yen-terminal/ghostty/zig-out/share/yen/themes/` | Upstream themes generated by the engine build |

Theme files hold literal colors because they are portable content; app chrome uses semantic tokens.
Tab sidebar rows use a neutral selection fill and the terminal-facing corner radius.
In the sidebar, an uncolored tab shows a terminal glyph and a colored tab shows its swatch.
Pane gutters use a 4-point inset on each side of a divider.
AppKit supplies the tab accessory’s trailing margin.
Headers and panel contents use a 12-point inset.
Split headers use the system caption for the pane title and directory, with semibold weight for the title.
The native tab and split header share the same activity icon.
Never turn palette values into design tokens, and never edit generated upstream theme sources.

## File Format

Plain `key = value` lines; the display name is the file name without an optional `.yen` suffix.
The engine opens `<themes directory>/<theme value>` verbatim, so Settings writes the file name (`ThemeInfo.configReference`), never the display name: a user theme saved as `Name.yen` resolves only as `theme = Name.yen`.
Previews need `background`, `foreground` and `cursor-color`; common extras are `cursor-text`, `selection-background`, `selection-foreground`, and `palette = <index>=<hex>` for ANSI 0–15.

## Bundling

`yen-terminal/customizations/bundle-yen-resources.sh`:

1. Resolves each manifest entry from `customizations/themes/` first, then upstream.
2. Normalizes the copy through `scripts/theme-contrast.js` so foreground, cursor and selection meet YEN's contrast floor, without touching upstream files.
3. Copies the curated set and both manifest files into `Resources/yen/`.
4. Checks that the tags file covers the manifest exactly with allowed tags only.
5. Fails when the count leaves 16–24, an entry is duplicated or missing, `YEN`, `Retro Terminal` or `CutePretzel` is absent, or a retired `Resources/yen/themes-full/` directory remains.

## Runtime

User themes load before bundled ones, bundled themes are filtered by the shipped manifest, and the first name wins, so a user theme overrides a bundled one.
Pinned themes (`pinnedThemeOrder`) come first, then manifest order; search matches names and tags.
A click applies the theme after a 150ms debounce, strips explicit color keys from `config.yen` so the theme's colors take effect, and reloads silently.
`ThemePreviewCoordinator` owns preview, snapshot, revert and commit through the `ThemePreviewHost` protocol; the pure config transforms stay as `SettingsController` statics for tests.
Theme files never travel in a settings export; an unresolvable theme name is rewritten to `YEN`.
Runtime discovery never migrates from `~/.yen/themes`.

**Engine resolution.** The engine, not Settings, decides what the terminal draws.

- It loads the theme first and then replays every loaded config file over it, so an explicit color key outside the theme wins.
- Settings strips color keys only from the managed `~/Library/Application Support/com.yenchat.yen/config.yen`; the engine also loads `$XDG_CONFIG_HOME/yen/config` and `config.yen`, a legacy Application Support `config`, and every `config-file` include.
- Names resolve by file name. The catalog matches case, spaces, dashes and underscores loosely, and the engine does not, so a name the picker shows as selected can still fail to load.
- A config with no `theme` line draws the engine's built-in colors, not the `YEN` theme, and no tile shows as selected.
  `ThemeConfigRepair` runs in `AppDelegate.init` before the engine reads config and writes `theme = YEN` when the key is missing or names a theme file that no longer exists; a user theme named without its `.yen` suffix is pointed at the file instead.
  It leaves the file alone when it holds explicit color keys, when another default config file exists, when the theme is a path or a `light:,dark:` pair, and when the build does not ship the `YEN` theme.
- Reset All Settings selects `YEN` rather than removing the key.
- Removing a theme from the manifest is safe for configs that name it only because of that repair; keep both in the same release.
- Chrome beside the terminal reads `TerminalChromeAppearance`, which republishes the app-level config background. Never re-derive a chrome color from the catalog by theme name.

The `YEN` theme keeps `cursor-color` and `selection-background` at `#ff5100` with `cursor-text` and `selection-foreground` at `#1e2029`, which keeps the brand accent readable at WCAG AA in full-screen TUIs.
The clean-checkout contrast test covers every tracked custom theme, and the bundler validates the whole generated catalog.

## Maintaining

1. Edit `customizations/themes/`, then the manifest (stay within 16–24, keep the pinned three) and the tags file.
2. Update `pinnedThemeOrder` if the theme should be pinned.
3. Run `./scripts/manual/26-sync-theme-catalog.sh` and commit the regenerated section below; run it again after a vendor refresh changes upstream themes.
   Seventeen catalog entries are upstream files, so a vendor refresh that renames or removes one fails the bundling step and lists the missing names; replace the entry in the manifest and the tags file, then run the sync script.
4. Run the targeted Settings theme suites (`_docs/09-quality.md` → Native Test Suite).

## Design System

**Brand.** The website uses phosphor green, dark chrome and theme-aware paper and ink.
The ASCII logo in `yen-welcome.sh` is pinned to brand orange with true-color ANSI (`\033[38;2;255;81;0m`) and never follows the theme.

**CSS structure.** Shared tokens and utilities live in `app/globals.css`.
It imports the journal and policy layouts from `app/editorial.css`.
The stylesheet uses `@utility` for classes that need variants (`lg:`, `hover:`), `:root` and `.dark` for HSL channel values, `@theme` mapping them to Tailwind tokens, `@theme inline` for `next/font` variables (defined on `<body>`), `@layer base`, and `@layer components` for variant-free classes.
Only `@utility` classes accept variants in Tailwind v4.
Dark mode is `next-themes` switching the `.dark` overrides; text tokens meet WCAG AA in both modes.
The header and footer are dark in both modes, so `html`, `body` and the `theme-color` meta use the dark chrome color `--ph-night` (`COLORS.chrome`) in both modes; `PageShell` paints the theme background on its own box.
Phones paint the root color in the safe areas, behind a collapsed toolbar and in overscroll, so a light root shows as a band below the footer; `tests/166-mobile-root-backdrop.test.ts` guards it, and only the iOS Simulator or a phone shows it, never headless Chrome.

**Utilities to reuse, never re-create:**

- Layout: `container-page`, `container-centered`, `section-padding`.
- Type: `text-heading-lg|md|sm`, `text-body`, `text-body-sm`, `text-body-xs`, `heading-spacing`.
- Text colors: `text-text-primary`, `text-body`, `text-text-muted`, `text-text-tertiary`, `text-text-inverse`; brand via `text-brand`, `text-brand-dark`, `bg-brand`.
- Components: `link-brand`, `nav-link`, `nav-link-active`, `nav-link-inactive`, `ph-primary`, `callout-card`, `media-border`, `media-caption`, `status-indicator`, `skip-link`, `focus-ring`.
- Terminal and code: `terminal-window`, `terminal-header`, `terminal-dots`, `terminal-content`, and the always-dark `code-*` tokens.

**Components.** Every public page uses `PageShell`, never a hand-rolled header without mobile-nav state.
Header and footer navigation links share `nav-link` / `nav-link-inactive` (see `components/shared/{header,footer}.tsx`); do not size footer links down with `text-body-xs`.
The homepage field guide uses native disclosures within the Phosphor grid.
Direct section links open the relevant chapter.
Terms opens with a desktop privacy receipt and direct policy links.
The blog opens with the original onigiri illustration and a chronological index.
Article text and weekly release entries share the field guide’s theme-aware reading colors.
Public pages do not include AI-summary buttons or links that send page URLs to external assistants.
Page titles use the shared sans family.
Terminal output, commands, and instrument labels use the shared monospace family.
Code examples use `TerminalCodeBlock` (`wrap` for prose-style blocks); framed tables and embeds use `TerminalPanel` (`components/docs/terminal-panel.tsx`).
The product manual uses `text-body` for paragraphs, lists, tables, and disclosure summaries; subsection headings use semantic `h3` elements with `text-heading-sm`.
Do not shrink ordinary instructions or use muted text as a second body style.
`inline-code-brand` inherits its surrounding font size; code blocks retain their shared monospace treatment.

Phosphor uses the responsive `ph-wrap` width for the hero, demos, field guide, and release log.
Policy and journal indexes use native disclosures and fragment links that work before hydration.

**Rules.**

- Tailwind v4 utilities only, no shadcn, no inline styles, no `!important`-style overrides.
- Use type tokens (`text-heading-md`), never raw `text-2xl font-bold`.
- No developer language on public pages ("scaffold", "MVP", "v1").
- Breakpoints are Tailwind defaults (`sm` 640, `md` 768, `lg` 1024), mobile first.

The homepage uses a fixed dark surround for the phosphor monitor and terminal previews.
Its field guide follows the site theme, and the heading renders in full without animation.
